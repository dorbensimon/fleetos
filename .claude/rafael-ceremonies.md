## Sprint Planning — 2026-08-25 — פיצ'ר "מסמכים" (שלב 1)
- **משתתפים (בפועל/מדומים):** רפאל (מתכלל), בהתבסס על דרישה ישירה של דור. עידן/מיקה/רועי/מתן/לירון טרם הופעלו בפועל — זהו תכנון מוקדם שמייצר להם briefing.
- **סטטוס שהוצג:** בקשה חדשה מדור — "מסמכים" בתפריט אדמין: יצירת מסמך (שם+קובץ), רשימת מסמכים, שליחה לנהג בודד או לכולם, קבלה אצל הנהג ב"מסמכים" עם אותו שם, התראה לנהג "מסמך X נשלח אליך לצורך חתימה". דור ציין מפורש שזה שלב ראשון, בלי מימוש חתימה בפועל (pad), וש"אחרי זה נתקדם".
- **בדיקת מוכנות טכנית (build-readiness) שביצע רפאל:**
  - טבלת `documents` הקיימת (bucket פרטי, owner_type driver/vehicle) **לא מתאימה כמות שהיא** למודל תבנית+שליחות מרובות — נדרשת החלטת סכימה.
  - טבלת `notifications` הקיימת **אין לה מודל נמען יחיד** (רק company-wide RLS ל-admin) — נדרש שינוי סכימה אמיתי כדי שנהג יראה התראה שנשלחה אליו ורק אליו. זה החסם הטכני המרכזי.
  - יש כבר תשתית UI קיימת שאפשר לעשות reuse: `Select` (בחירת נהג), `EmptyState`, מסך `MenuScreen.tsx` (הוספת item "מסמכים" קלה), `DriverNotificationsScreen.tsx` כבר קיים וריק עם הערה בקוד שמצפה בדיוק לפיצ'ר הזה ("that lands with the document-signature feature").
- **סדר עבודה מוצע (Task Breakdown + תלויות):**
  1. **עידן** — PRD קצר לפיצ'ר "מסמכים — שלב 1", כולל: הבהרת גבולות (בלי חתימה), מענה לשאלות הפתוחות (ראו `.claude/rafael-risks.md`: גודל/סוג קובץ, מחיקה/עריכה אחרי שליחה, נהג לא-פעיל, "שליחה לכולם" האם כולל נהגים עתידיים). **לא מתחיל אף אחד אחר עד שזה קיים**, כי בלעדיו יש סיכון scope-creep/הנחות סותרות.
  2. **מיקה + רועי (מקביל, אחרי PRD)** — תכנון סכימה: טבלאות חדשות למסמכי-תבנית ולשליחות, פתרון לנמען יחיד ב-`notifications` (או טבלה/מנגנון מקביל), RLS מלא (נהג רואה רק מסמכים שנשלחו אליו; אדמין רואה הכל בחברה שלו), מדיניות Storage לbucket הרלוונטי.
  3. **רועי** — מימוש מיגרציה + פונקציות/API (יצירת מסמך, שליחה לנהג/לכולם, יצירת התראה מקושרת).
  4. **מתן** — UI: מסך "מסמכים" באדמין (רשימה + הוספה), מסך מסמך בודד עם "שליחת מסמך" (בחירת נהג / שליחה לכולם), הוספת item לתפריט (`MenuScreen.tsx`, גם ADMIN_ITEMS וגם DRIVER_ITEMS), אזור "מסמכים" אצל הנהג, חיבור להתראה הקיימת (`DriverNotificationsScreen.tsx` כבר יש שלד).
  5. **לירון** — standby: נכנסת רק אם מתן מזהה שאין דפוס UI מתאים ל-reuse (סביר שרוב הרכיבים כבר קיימים — Select, list rows, VehicleDriversEditor כהשראה לבחירת נהג).
  6. **עומר** — QA אחרי שרועי+מתן מסיימים implementation ראשונית: בדיקת RLS (נהג לא רואה מסמכים של נהג אחר), בדיקת "שליחה לכולם" בקנה מידה, בדיקת שם המסמך זהה בשני הצדדים.

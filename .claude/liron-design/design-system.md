# Design System — תוספות עבור "מסמכים חתומים" שלב 2

**שלב בתהליך:** 4. עיצוב (Design) + 6. מסירה (Handoff)
**תאריך:** 2026-08-25
**מבוסס על:** `lib/theme.ts` (מקור אמת יחיד לטוקנים — לא הומצאו טוקנים חדשים) ו-`components/ui/index.tsx` (רכיבים גנריים קיימים ל-reuse)

כל הרכיבים כאן **מרחיבים** את ה-Design System הקיים — לא מחליפים אותו. שימוש חוזר מוצהר ברכיבי `components/ui`: `Screen`, `ScreenHeader`, `AppText`, `Card`, `PressableCard`, `PrimaryButton`, `SecondaryButton`, `Field`, `LoadingState`, `EmptyState`, `ErrorState`, `useToast`.

## רכיב 1 — SignaturePad (קנבס חתימה, צד נהג)

**תיוג: UX (לוגיקת המצבים) + UI (מראה).**

### מטרה
לכידת ציור חופשי (קו חתימה) לפני קידוד ל-PNG שקוף ושליחה לשרת (ר' contract במיגרציה 38, סעיף 3 — הקנבס לא אחראי על מיקום/הטבעה, רק על capture).

### מבנה
```
┌─────────────────────────────────────┐
│  חתימה על המסמך                      │  ← כותרת (TYPO.sectionTitle)
│  "נוהל בטיחות בדרכים"                │  ← שם המסמך (TYPO.bodyMuted)
│                                       │
│  ┌─────────────────────────────────┐ │
│  │                                 │ │  ← קנבס: רקע COLORS.field,
│  │        (אזור ציור)              │ │    מסגרת מקווקוות COLORS.fieldBorder,
│  │                                 │ │    גובה קבוע ~180-220,
│  │  חתום כאן ✕ (placeholder טקסט   │ │    RADIUS.md
│  │  כשריק, נעלם ברגע שמתחילים לצייר)│ │
│  └─────────────────────────────────┘ │
│                                       │
│  [שגיאה: "יש לצייר חתימה לפני האישור"]│ ← מוצג רק לאחר ניסיון אישור על ריק
│                                       │
│  [ נקה ]           [ אשר וחתום ]     │  ← SecondaryButton | PrimaryButton
└─────────────────────────────────────┘
```

### מצבים (Design Tokens בפועל)
| מצב | קנבס | כפתור "נקה" | כפתור "אשר וחתום" |
|---|---|---|---|
| **Default (ריק)** | רקע `COLORS.field`, מסגרת מקווקוות 1.5px `COLORS.fieldBorder`, placeholder טקסט "חתום כאן" ב-`COLORS.textFaint` | `disabled` (opacity 0.5, לא ניתן ללחיצה — אין מה לנקות) | `PrimaryButton` פעיל (`COLORS.accent`) — הלחיצה עצמה מבצעת את הוולידציה, לא ה-disabled state (כדי שהודעת השגיאה תוצג בבירור, לא רק "כפתור אפור" חסר הסבר) |
| **Drawing (מצייר עכשיו)** | קו נמתח בזמן אמת, צבע דיו `COLORS.text` (#1A1A1A), עובי קו 2.5px | פעיל | פעיל |
| **Drawn/Filled** | קו/חתימה שמורה על הקנבס, מסגרת עוברת ל-`COLORS.accent` (משוב עדין שיש תוכן תקף) | פעיל | פעיל |
| **Error (ניסיון אישור על ריק)** | מסגרת הופכת רגעית ל-`COLORS.dangerText`, מוצג טקסט שגיאה מתחת (`COLORS.dangerText`, TYPO.caption) — "יש לצייר חתימה לפני האישור" | ללא שינוי | ללא שינוי (המשתמש יכול לנסות שוב) |
| **Submitting (אחרי לחיצה על אישור תקין)** | קנבס `disabled` (לא ניתן לגעת בו), overlay `ActivityIndicator` באמצע | `disabled` | `PrimaryButton loading` (spinner, כמו `PrimaryButton` הקיים) |
| **Submit failed** | חוזר ל-Drawn (החתימה **נשארת מצוירת על המסך** — לא נמחקת אוטומטית, כדי שהנהג לא יצטרך לצייר שוב בגלל כשל רשת) | פעיל | פעיל, טקסט שגיאה כללי מוצג (Alert או inline, בהתאם לדפוס השגיאות הקיים באפליקציה — Alert.alert משמש כיום ברוב הזרימות, ר' DocumentTemplateDetailScreen) |
| **Read-only (מסמך כבר signed — לא state של הרכיב עצמו, אלא היעדרו)** | הרכיב **לא מוצג כלל** במסך פרטי מסמך signed — רק תצוגת PDF | — | — |

### פרטי מימוש קריטיים למתן
- **פלט**: PNG בלבד, **רקע שקוף**, גודל קובץ קטן (מיגרציה 38: "a few hundred KB is generous"). זהו הפלט היחיד שנשלח לשרת — **לא** קואורדינטות, לא claim על מיקום.
- **צבע דיו מומלץ**: `COLORS.text` (#1A1A1A) על שקוף — לא שחור טהור, לשמירה על אחידות עם שאר הטיפוגרפיה של המוצר. (זוהי המלצת UI שלי — לא נדרש טכנית ע"י ה-schema; אם מתן מעדיף שחור טהור לצורך קריאות/סריקה טובה יותר בהדפסה, זה שיקול טכני לגיטימי לשנות).
- **ולידציית "ריק"**: קו מינימלי — הגדרה מוצעת: לפחות נקודה/מקטע אחד שצויר (לא "0 פיקסלים נצבעו"). מתן קובע את הסף המדויק (למשל: bounding box של הציור > 0).
- **גישה נגישות**: כפתור "אשר וחתום" חייב `accessibilityLabel` ("אישור וחתימה על המסמך") ו-`accessibilityHint` שמסביר שהפעולה סופית ("לאחר האישור לא ניתן לערוך את החתימה") — תואם FR3/הנחה #3 (סופיות).
- **מיקום ה-signature pad ביחס למסך פרטי מסמך**: מסך אחד (לא מודאל) — ר' `information-architecture.md` סעיף 2. Trade-off שנשקל: מודאל מהיר יותר לבנייה, אך מסך מלא נותן יותר מקום לקנבס נוח לציור באצבע (חשוב לחוויית "בשטח" שה-PRD מדגיש) ולכפתור "צפייה במסמך" הצמוד. **המלצתי: מסך מלא.**

## רכיב 2 — SignatureAreaMarker (סימון מיקום חתימה, צד אדמין, FR1)

**תיוג: UX (חדש לגמרי — לא היה קיים בשלב 1) + UI.**

### מבנה (אופציה C, ר' `information-architecture.md` סעיף 4)
```
┌─────────────────────────────────────┐
│  מיקום החתימה בטופס                  │  ← TYPO.sectionTitle
│  סמן היכן על הטופס הנהג יחתום        │  ← TYPO.bodyMuted
│                                       │
│  עמוד:  [1] [2] [3] [4]              │  ← chips, כמו FilterChips הקיים,
│                                       │    רק עמודים 1..N לפי הקובץ (ברירת מחדל: 1)
│                                       │
│  ┌───────────────────┐               │  ← תרשים עמוד סכמטי, יחס A4 (1:1.41),
│  │                   │               │    רקע COLORS.field, מסגרת COLORS.fieldBorder
│  │                   │               │
│  │        ┌────┐     │               │  ← תיבת חתימה: רקע COLORS.accentSoft,
│  │        │ ✎  │     │               │    מסגרת מקווקוות COLORS.accent,
│  │        └────┘     │               │    ניתנת לגרירה + ידית שינוי-גודל בפינה
│  │                   │               │
│  └───────────────────┘               │
│                                       │
│  📄 פתח את ה-PDF לצפייה               │  ← SecondaryButton, אותו getTemplateFileUrl הקיים
│                                       │
│  [שגיאה: "יש לסמן מיקום חתימה"]       │  ← מוצג רק בניסיון שמירה בלי תיבה ממוקמת
└─────────────────────────────────────┘
```

### מצבים
| מצב | תיאור |
|---|---|
| **Default (אין תיבה עדיין)** | התרשים ריק, טקסט הנחייה במרכזו: "הקש כדי למקם תיבת חתימה" |
| **תיבה ממוקמת** | תיבה נראית עם ידית גרירה (מרכז) וידית שינוי-גודל (פינה תחתונה-שמאלית, מותאם RTL) |
| **גרירה פעילה** | התיבה עוקבת אחר האצבע, מוגבלת לגבולות התרשים (לא יכולה לצאת מהעמוד — תואם CHECK constraint בשרת) |
| **החלפת עמוד** | מעבר בין chips "עמוד" **לא** מוחק תיבה שכבר הוגדרה בעמוד קודם אם המשתמש חוזר אליו — אבל **יש תיבה אחת בלבד לכל התבנית** (הנחת עבודה #6 ב-PRD): מעבר עמוד מזיז את התיבה הקיימת ליעד החדש (עדכון `signature_page`), לא יוצר תיבה נוספת |
| **שגיאת שמירה (אין תיבה)** | טקסט שגיאה אדום מתחת לתרשים, תואם ל-`Field error` הקיים ברכיבי `components/ui` |
| **Immutable אחרי שמירה** | לאחר יצירת התבנית, מסך זה לא נגיש שוב לעריכה — אין מסך "ערוך מיקום חתימה" (תבנית immutable, כמו היום) |

### פרטי מימוש קריטיים למתן
- ערכי היציאה של הרכיב: `signature_page` (int), `signature_x`, `signature_y`, `signature_width`, `signature_height` (כולם 0..1, יחסית לתרשים הסכמטי) — ממופים ישירות לעמודות ב-`document_templates` (מיגרציה 38, סעיף 1). **חשוב:** מכיוון שהתרשים סכמטי (לא רינדור אמיתי של ה-PDF), יחס הגובה/רוחב שלו חייב לשקף A4 פורטרט (היחס הנפוץ ביותר לטפסים) — אם ל-PDF בפועל יחס שונה, המיקום היחסי (0..1) עדיין תקף מתמטית, אבל ייתכן שיראה מעט "לא מדויק" ויזואלית ביחס לתוכן האמיתי. זהו trade-off ידוע של אופציה C, לא באג.
- מינימום גודל תיבה: 1% מרוחב/גובה העמוד (תואם `document_templates_signature_box_range_check` בסכימה, `>= 0.01`) — יש לאכוף גם ב-UI (לא לאפשר גרירה לגודל 0), לא רק לסמוך על השרת לדחות.
- שילוב בטופס הקיים: מתווסף כ**שלב שלישי** בתוך אותו modal/sheet של "הוספת מסמך" ב-`DocumentTemplatesScreen.tsx` (לא מסך נפרד) — עקבי עם המבנה הקיים (שם → קובץ → כעת: מיקום חתימה), עם ולידציה חוסמת לפני שמירה (FR1 קבלה).

## רכיב 3 — תצוגת "מסמכים חתומים" בפרופיל נהג, צד אדמין (FR5/FR6)

**תיוג: UX (זרימה, ולידציית סטטוס) + UI (עקבי לגמרי עם `DriverSignedDocumentsScreen` הקיים אצל הנהג).**

### כניסה — שורת תפריט חדשה ב-DriverDetailScreen
נוספת לרשימת `MENU` הקיימת (`styles.menuRow`, אותו component pattern), **לא** כרטיס נפרד:
```
[ 📄  מסמכים חתומים                              ›  ]
```
זהה ויזואלית לשאר שורות התפריט הקיימות (`menuIcon` + `menuLabel` + `chevron-back`) — **החלטת UI: reuse מלא, אין רכיב חדש כאן.**

### מסך הרשימה (DriverSignedDocumentsAdmin)
עיצוב זהה כמעט 1:1 ל-`DriverSignedDocumentsScreen.tsx` הקיים (אותו `Card`, `STATUS_LABEL`, pill), בתוספת:
```
┌─────────────────────────────────────┐
│  📄  נוהל בטיחות בדרכים               │
│      12/08/2026            [נחתם]    │  ← pill ירוק, כמו היום
├─────────────────────────────────────┤
│  📄  טופס ויתור סודיות                │
│      20/08/2026          [ממתין]     │  ← pill אפור/accent-soft, כמו היום
└─────────────────────────────────────┘
```
- שורת **signed**: לחיצה פותחת תצוגת המסמך החתום המלא — מודאל/מסך עם:
  - `InfoRow` "נחתם בתאריך" עם `formatDate(send.signed_at)` (רכיב קיים, ר' `components/ui`)
  - **שתי פעולות נפרדות וברורות, לא כפתור אחד** (עדכון 25.8.2026, לפי FR5 בנוסף ל-FR6 — צפייה היא דרישה עצמאית, לא רק שלב-ביניים לפני הורדה):
    1. **`SecondaryButton` "צפייה במסמך" (FR5)** — icon `eye-outline`. פותח את המסמך החתום **לצפייה בלבד**, `Linking.openURL` אל signed URL של `signature_file_path` (אותו דפוס אבטחה/TTL כמו `getSendFileUrl`/`getTemplateFileUrl` הקיימים — לא קישור ציבורי, לא רינדור PDF פנימי חדש). **קריטי:** ה-URL הוא תמיד עבור `signature_file_path` (הטופס המלא + חתימה), **לעולם לא** `file_path` המקורי הבלתי-חתום, גם אם שתי העמודות קיימות על אותה שורה.
    2. **`PrimaryButton` "הורדת המסמך החתום" (FR6)** — icon `download-outline`. שומרת בפועל את הקובץ למכשיר האדמין (לא רק פותחת אותו לצפייה).
    - סדר מוצע ב-UI: "צפייה" מעל "הורדה" (secondary מעל primary) — צפייה היא הפעולה הנפוצה/מהירה יותר (בדיקת סטטוס מהירה), הורדה היא פעולה "כבדה" יותר (שמירה קבועה למכשיר) שמוצדק שתהיה הכפתור הבולט ביותר אך לא היחיד.
- שורת **pending**: לחיצה **לא** פותחת דבר, ואין כפתור צפייה או הורדה כלל (אין קובץ חתום קיים) — תואם FR5 קבלה: "אדמין הפותח שליחה בסטטוס pending לא רואה טופס חתום — רק את הסטטוס 'ממתין'".

### מצבי כפתורי צפייה/הורדה (FR5/FR6)
| מצב | "צפייה במסמך" (FR5) | "הורדת המסמך החתום" (FR6) |
|---|---|---|
| **Default (signed)** | `SecondaryButton` רגיל | `PrimaryButton` רגיל, `COLORS.accent` |
| **פועל (loading)** | לא נדרש spinner ייעודי — פתיחת URL חיצוני היא כמעט מיידית (כמו `viewPdf`/`openDocument` הקיימים) | `PrimaryButton loading` (spinner קיים ברכיב) |
| **הצלחה** | נפתח בדפדפן/צופה PDF חיצוני של המכשיר — אין משוב נוסף נדרש באפליקציה עצמה (עקבי עם `Linking.openURL` הקיים) | Toast קיים (`useToast`) — "המסמך נשמר במכשיר" |
| **כשל** (signed URL לא נוצר) | `Alert.alert` — "לא ניתן לפתוח את המסמך כרגע" (אותה הודעה בדיוק כמו `openDocument`/`viewPdf` הקיימים היום) | `Alert.alert` (דפוס קיים באפליקציה) — הודעת שגיאה בעברית, לא stack trace |
| **pending** | הכפתור **לא קיים כלל** בשורה הזו | הכפתור **לא קיים כלל** בשורה הזו (לא disabled — נעדר, כי אין קובץ להוריד, FR6 קבלה) |

### הבחנה קריטית מ-DocumentTemplatesScreen/DocumentTemplateDetailScreen
**אין לגעת** במסכי התבניות הקיימים — לא עמודת סטטוס, לא מונה "כמה חתמו". זו לא המלצת עיצוב אלא הגדרת היקף מפורשת מה-PRD (FR5) — מוזכר כאן כדי שמתן/עומר לא יראו את זה כ"נשכח".
